Inbound Support & Routing Agent for Vantix

Vantix sells team workflow software. When someone calls the support line, this agent's first job is to figure out if they're an existing customer or a prospect — then either answer from the knowledge base or route straight to Sales.

B2B SaaS · Team Workflow Software Inbound · Voice AI Aircall Dashboard
  • ✓ An inbound agent that greets callers and sorts them with one clear yes/no question
  • ✓ A knowledge base covering the most common customer questions
  • ✓ A routing rule that sends non-customers to Sales instead of trying to support them
  • ✓ Full call logging so nothing gets lost
Build steps
1

Create your inbound AI virtual agent

Set up the agent shell in the Aircall dashboard before touching any scripts.

  • In the Aircall dashboard, open AI Voice Agents
  • Click Create an AI Voice Agent and select Inbound
  • Give it a name that reflects Vantix and the support context
2

Write the agent's opening message

This is the receptionist moment — the whole routing decision hinges on one clear yes/no question, asked right away.

  • Go to the Call script tab in the agent settings
  • Find the Greeting message field
  • Keep it to one question — don't add anything else
  • Example: "Hi, thanks for calling Vantix, I am an AI assistant! Quick question before we dive in, are you already a Vantix customer, or are you exploring Vantix for the first time?"
Tip 1 — the opening and farewell message are read out loud word for word. Make sure to write exactly what you want to be said, in the desired language.
Tip 2 — imagine you're a customer calling in with a real problem. What's the fastest way to find out if you even belong on this line?
3

Write the agent's behaviour prompt

Two branches: existing customers get support-mode answers from the knowledge base, everyone else gets a clean handoff to Sales.

  • In Call script → Conversation guidelines, describe the agent's routing logic and tone
  • If they say yes (existing customer): switch into support mode and answer only from the knowledge base
  • If they say no (prospect / not yet a customer): don't pitch or answer product questions — explain the handoff to Sales and transfer
  • Define when a support conversation wraps up — once the question is answered or the agent has nothing more it can help with from the knowledge base
Tip 1 — think of this as a receptionist who seamlessly becomes a support rep, not two separate people. The yes/no question is the only routing step.
Tip 2 — don't be afraid to experiment and play around with the prompt — see what works best for you and fulfills your requirements.
## Identity & Routing
- Always ask the customer/prospect qualifying question first, before anything
  else
- If the caller is an existing customer: proceed to Support Mode
- If the caller is not a customer, or unsure/exploring: proceed to Sales
  Handoff
- Ask one clarifying question if the answer is ambiguous, then make a routing
  decision - don't loop

## Support Mode
- Answer only from the knowledge base
- Ask one question at a time
- If the answer isn't in the knowledge base, say so honestly and offer to
  connect them with a human rather than guessing
- Never invent pricing, features, or timelines

## Sales Handoff
- Do not attempt to answer product or pricing questions yourself
- Explain briefly that you're connecting them with the Sales team
- Initiate the transfer

## Closing
- Wrap up once the caller's question is answered or they've been handed off
  to a human
- Thank the caller before ending the call
4

Build the knowledge base

A centralized library of information about Vantix — products, services, and frequently asked questions — that the agent refers to whenever it's asked a question.

  • Go to the Knowledge sources section of your agent
  • Add a Block of content as a knowledge source
  • Cover the questions a Vantix customer is likely to ask
  • Think about: resetting a password, understanding a bill or plan, exporting data, connecting an integration, cancelling a subscription
  • Write these as short, clear answers — the agent will use them to respond naturally
5

Set up the Sales transfer branch

This is the routing mechanism — it's what turns the yes/no answer into an actual outcome instead of just a conversation.

  • Go to Call transfer rules → Transfer branches
  • Add a branch, e.g. "New / Prospective Customer"
  • Set the trigger condition: the caller says they are not yet a customer, or asks about pricing, demos, or signing up
  • Write a short transfer message
New / Prospective Customer
The caller says they are not yet a customer, are exploring Vantix for the first time, or asks about pricing, a demo, or signing up.
"Let me connect you with our Sales team who can help you get started."
This is the routing mechanism — it's what turns the yes/no answer into an actual outcome instead of just a conversation.
6

Set up data capture for anything support can't resolve

Make sure a human rep never has to start from zero.

  • Go to the Intake questions section
  • Write the questions the agent should ask if it can't fully resolve a request from the knowledge base
  • Cover: a short description of the issue, and the best callback number or email
Can you describe the issue in a bit more detail?
Gives a human rep the context to pick up the conversation without starting over.
What's the best number or email to reach you at?
Ensures the follow-up can happen even if the caller can't be reached again immediately.
Don't use too many intake questions — only capture the information you really need. Keeping it light is the way to go.
7

Test your agent

Save it, call it, and listen back like a customer would.

  • Save your configuration
  • Use the Test agent call button at the top right of the agent's settings page
Tip 1 — did the yes/no question feel natural? Did the agent actually stop pitching once you said "no"? Adjust and test again.
Tip 2 — encountered multiple issues while testing? Focus on one problem at a time — reproduce it, fix it, then test it before moving on to the next.
